# tools 目录说明

`tools/` 目录用于存放所有可复用的小工具，并按照使用场景或运行环境划分子目录。每个工具都应包含说明文档、源码以及必要的示例或资源文件。

## 分类结构
| 目录 | 说明 | 典型内容 |
| --- | --- | --- |
| `scripts/` | 跨平台或命令行脚本（Python、Shell、PowerShell 等） | 单文件脚本、命令行工具、自动化流程 |
| `web/` | 轻量级网页或前端/后端演示项目 | 静态页面、前端 demo、简易服务端脚本 |
| `windows/` | Windows 平台专用脚本或工具 | `.bat`、`.ps1`、注册表配置等 |
| `linux/` | Linux/Unix 环境专用脚本或服务配置 | `systemd` 配置、运维脚本等 |
| `latex/` | LaTeX 模版与排版工具 | 学位论文模版、排版脚本 |
| `meta/` | 与仓库维护、工具集合或流程相关的元信息 | 维护指南、索引型工具 |

如有新的分类需求，可在提交 PR 时说明使用场景，并在此表格中补充描述。

## 工具目录结构规范
每个工具目录建议遵循以下结构（可根据实际需求增删）：
```
<category>/<tool-name>/
├── README.md          # 工具说明（使用模板，可根据需要扩展）
├── src/ 或 scripts/    # 主要源码或脚本文件
├── assets/            # 演示截图、示意图等（可选）
└── LICENSE            # 若工具使用不同于仓库默认的许可（可选）
```

为保持一致性，推荐使用 [`../docs/TOOL_TEMPLATE.md`](../docs/TOOL_TEMPLATE.md) 作为文档模板，并在 README 中提供以下信息：
- 工具简介、适用场景
- 依赖与环境要求
- 安装/运行步骤
- 示例或常见问题
- 维护者或联系方式（可选）

## 添加新工具时的步骤
1. 在合适的分类目录下创建新的工具目录，例如 `tools/scripts/my-tool/`。
2. 根据模板撰写工具说明，并将源码及资源放入同级目录。
3. 更新仓库根目录的 [工具目录](../README.md#工具目录) 表格，补充新工具信息。
4. 在 Pull Request 中描述工具用途、验证方式以及与校园场景的关联。

保持文档清晰、目录结构统一有助于他人快速理解和复用你的贡献。
